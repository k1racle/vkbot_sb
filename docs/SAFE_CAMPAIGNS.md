# Кампания «Сейф»

В разделе «Кампании» выберите режим «Сейф — один код, одна попытка, один победитель». Укажите конкретный пост, четырёхзначный код, будущую дату начала и дату окончания приёма кодов (время Москвы). Настройте приглашение, ответы и обычный подарок: промокод, сообщение, ссылку, при необходимости файл.

После первого включения фиксируются пост, даты, код и тексты результатов. Пауза не сбрасывает попытки и победителя. Для следующего розыгрыша нужна новая кампания. Приз физического бокса означает сообщение о победе и запись победителя в таблице; отправку самого бокса организует бренд.

## Подключение VK

- В Callback API включите `wall_reply_new`, `wall_reply_edit`, `wall_reply_delete`, `wall_reply_restore`, `message_new`, `message_allow`, `message_deny`.
- В настройках проекта сохраните пользовательский токен администратора с доступом к чтению стены, в поле «Пользовательский токен для видео и проверки сейфа». Существующее зашифрованное хранилище токена используется и для чтения комментариев. Участникам бот пишет только токеном сообщества.
- Чтение списка комментариев `wall.getComments` официально поддерживает пользовательский/сервисный токен, а не токен сообщества: [схема методов VK](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json). Без рабочего токена подтвердить главный приз нельзя: попытка сохранится, участник сможет повторить проверку после исправления подключения.
- Для личного приглашения требуется разрешение на сообщения сообщества. Если его нет, под комментарием остаётся ссылка на чат: участник нажимает «Начать» или пишет «Сейф», затем «Проверить код».

## Правила и результат

Первый комментарий из четырёх ASCII-цифр `0–9` в периоде `[начало, конец)` расходует попытку аккаунта в этой кампании. Пробелы по краям игнорируются. `0047` и `1111` допустимы; фразы с цифрами, несколько кодов и цифры других алфавитов не учитываются. Ответы в ветках комментариев тоже участвуют. Плюс-слова, стоп-слова, минимальная длина и отключение ограничения повторов для сейфа не применяются.

Повторные комментарии не заменяют код и не вызывают новые приглашения. Повтор события того же первого комментария может повторить неудавшуюся доставку с тем же идентификатором отправки. При переставленных событиях VK первым считается опубликованный раньше: время VK, затем меньший ID комментария при совпавшем времени.

Кнопка привязана к аккаунту и сохранённой попытке. Пользователь не вводит код заново в личке. Перед результатом проверяется подписка. Неверный код даёт утешительный ответ и бонус. Для верного кода бот читает комментарии поста и ветки, проверяет оригинал, порядок и подписку более ранних претендентов. Если более ранний подписанный претендент ещё не нажал кнопку, поздний получает пояснение и бонус, но не главный приз.

Первый подходящий участник получает сообщение о победе сразу после нажатия кнопки. Победитель закрепляется условным обновлением одной строки кампании **до отправки поздравления**. Сбой VK не освобождает приз для другого человека. Повторная кнопка после ошибки доставляет поздравление с прежним `random_id`. Другим авторам верного кода сообщается, что сейф открыли раньше.

Изменение, удаление или восстановление первого комментария до подтверждения победы аннулирует попытку и не даёт новую. После подтверждения победитель не меняется. Эти правила необходимо отразить в конкурсном посте вместо требования сохранить комментарий до конца игры. Подписка проверяется во время проверки кода, а не исторически на момент публикации.

Бонус отправляется отдельно один раз, включая победителя. Перед первой отправкой сохраняются точный текст, промокод и вложение; после ошибки используется тот же результат и `random_id`. Доставка внешнего сообщения зависит от идемпотентности VK. Запись выдачи в базе создаётся один раз.

## Проверка и ограничения

На странице кампании показаны первые коды, время, ссылки на комментарии и аккаунты, победитель, статус бонуса и ошибки доставки. Проверка отправки в админке отправляет только тестовый текст приглашения, без рабочей кнопки, участия, бонуса и победы.

Если VK не даёт полный список, список изменился во время проверки или виден более ранний комментарий без исходного события, главный приз не подтверждается. Участнику предлагается повторить проверку, подробности доступны в таблице. Не отключайте обработку событий проекта во время игры: восстановить первоначальный текст уже удалённого/отредактированного комментария после потери событий невозможно. Редактирование с возвратом исходного текста определяется по событиям редактирования, поэтому они обязательны.

Пауза кампании сохраняет новые попытки и изменения комментариев, но отключает приглашения и выдачу. Глобальный тестовый режим также отключает выдачу сейфа. После возобновления участник может написать «Сейф». Если правильный код никто не угадает, победителя не будет.

Миграция добавляет поля кампании, `safe_comments`, `safe_attempts` и ссылку в журнале диалогов. История обычных кампаний сохраняется; данные изолированы существующими базами/схемами проектов. Кампанию сейфа нельзя использовать для обычной выдачи промокода из визуального сценария.
